# CutRoom 0.6.1 — Modelo e raciocínio corretos

- Claude via terminal consulta o catálogo da CLI oficial, com nome, versão, ID resolvido, descrição e capacidades por modelo. A lista fixa Sonnet/Opus/Haiku foi removida; modelos adicionais e configurações de gateways podem aparecer conforme a CLI.
- A seleção inicial respeita o padrão da CLI. O modelo efetivamente informado pela resposta fica visível quando difere da seleção.
- Claude API, DeepSeek, OpenRouter e APIs compatíveis mostram os IDs dos modelos. O esforço usa os metadados de cada provedor; modelos sem essa capacidade não recebem um controle fictício.
- **Padrão do provedor** omite o esforço nos provedores não-Codex. O app deixa de forçar Alto ou o primeiro nível da lista. Esforços inválidos são rejeitados antes da chamada.
- A leitura do catálogo OpenRouter respeita `reasoning.supported_efforts`, `default_effort` e raciocínio obrigatório. Claude API usa pensamento adaptativo quando o modelo declara esse recurso e o usuário escolhe um esforço.

O editor continua gratuito; limites e custos dos modelos seguem sua conta. Atualize pelo instalador Windows x64, com o CutRoom fechado. A prévia continua sem atualização automática e sem assinatura digital.

Consulte o [guia de provedores](../providers.md) para detalhes e limites de validação.

## Validação

- 113 testes passaram, incluindo casos para catálogo oficial do Claude CLI, IDs resolvidos, modelos de gateway, esforços OpenRouter/Anthropic e identidade retornada em streaming.
- `npm run build` compilou o app Electron.
- A verificação do app empacotado passou por IPC real, edição e desfazer de timeline, cancelamento de streaming e descoberta dos provedores. A parte de modelos usou APIs locais simuladas; não fez inferência paga.
- A CLI oficial do Claude foi consultada no protocolo de catálogo sem enviar uma solicitação de geração.
